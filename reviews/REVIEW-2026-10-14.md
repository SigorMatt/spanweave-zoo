#### 1. Oversized length headers get no response

- **Severity:** Medium ("Remediation recommended")
- **Labels:** `🐞 Bug`, `☼ Reliability`
- **Anchored at:** `spanweave_zoo/sink.py[R156-158]` (PR diff, right side); inline comment `4265845477` on `spanweave_zoo/sink.py` lines 156–158, commit `fe9c08f`
- **Qodo finding id:** `07c6c11c-9738-42f0-a317-f76d50836048`

**Description.**

```text
declared_length() calls int(value) after checking only that the header contains ASCII digits, so
a value beyond Python's integer-conversion digit limit raises ValueError. When a POST carries such
a header, _read_body() lets the exception escape before the sink records the zero-byte body or
sends its unframed response.
```

**Code (as quoted).**

```diff
+    if not value or not set(value) <= _DIGITS:
+        return None
+    return int(value)
```

**Evidence.**

```text
The new conversion has no exception handling. The POST handler invokes it through _read_body()
before record() and _answer(), and its only local exception handler catches RecorderClosed.
```

**Evidence references** (blob at `fe9c08f`): `spanweave_zoo/sink.py[143-158]`; `spanweave_zoo/sink.py[660-675]`; `spanweave_zoo/sink.py[702-729]`; `pyproject.toml[7-28]`

**Fix focus areas:** `spanweave_zoo/sink.py[143-158]`; `spanweave_zoo/sink.py[702-711]`

**Recommended fix (Qodo's).** Catch conversion failure in `declared_length()` and return `None`, preserving the zero-byte, connection-closing response. Add a test with an all-digit header beyond the conversion limit.
