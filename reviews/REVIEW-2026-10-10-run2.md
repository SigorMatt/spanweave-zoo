## 2. Findings, binned

### Blocks Z4 capture

**Z-1 — Ctrl-C, the README's only way to end a capture, can mark a clean capture failed;
under load it did every time.**
- **Cause:** `otelcol-contrib` is spawned in zoo's process group (`collector.py:273-281`: no
  `start_new_session`/`process_group`), so a terminal's Ctrl-C reaches it directly. It logs
  `"signal": "interrupt"`, shuts down and exits 0. `check_collector()` (`capture.py:338-347`)
  records any exit, even after a stop was requested, and `stop()` checks only after `raw.stop()`
  (up to 50 ms, `capture.py:314-322`).
- **Result:** `problems: ["collector exited: 0"]`, exit 1, verify and `make check` red. A capture is
  immutable, so a Z4 capture taken this way is failed for good.
- **Frequency:**

  | where | stopped by | failed |
  |---|---|---|
  | the operator run in §1.5 | process-group SIGINT | 1/1 |
  | lead reviewer, scratch captures at HEAD | `setsid` + process-group SIGINT | 4/4 |
  | A3d reviewer | process-group SIGINT | 7/7 |
  | A3a reviewer, HEAD | `setsid` + process-group SIGINT | 2/37 |
  | A3a reviewer, HEAD | real tty Ctrl-C | 1/8 |
  | A3a reviewer, `2b3c499` | real tty Ctrl-C | 5/10 |
  | anyone | SIGINT or SIGTERM to the zoo PID alone | 0/19 |

  It is a race, and on a loaded machine it was lost every time.
- **Introduced by A3a:** the parent got the same signal but had no `problems`; 0/6.
- **Why the tests missed it:** A2's SIGINT test raises in-process with a fake launcher, and A3a's sets `exited=137`
  on a fake. Nothing signals a process group.
- **Fix, for the builder (spec first):** the child runs in its own process group, and/or an exit
  after stop was requested is not a problem. Add a test that signals the group. Until then, the
  only clean stop is `kill -INT <zoo pid>`, which is not what the README says.
- *(section-operator OP-1, section-a3a A3a-1, section-a3d A3d-1)*
