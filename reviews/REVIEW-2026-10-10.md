### 1.1 Claim 1 — A1, the sink (`69fb6bd`)

- **(a) gzip stored still-encoded — confirmed.** Live sink on 47731; `cmp` silent
  against the bytes sent; magic `1f 8b`; `file` says gzip; `Content-Encoding:
  gzip` verbatim in `0003.headers.json`; manifest `sha256 ca694738…bf83` is the
  **encoded** digest (decoded would be `8a3806d1…`), `bytes: 69` the encoded
  length. `zoo verify` passes, then exits 1 on one flipped bit.
- **(b) the sink parses nothing — confirmed.** Runtime import closure is
  `spanweave_zoo`, `.manifest`, `.sink` plus stdlib; no `gzip`, `zlib`, `brotli`,
  `google.protobuf`, `opentelemetry` or `_pb2` anywhere; zero runtime deps. The
  one `json.loads` (`manifest.py:80`) reads the sink's **own** `MANIFEST.json` —
  the exception `SPEC.md` §1.1 names — and `json.dumps` is serialization of the
  sink's own data, not parsing of a body. A body travels `rfile.read(length)`
  (`sink.py:194`) → `write_bytes` (`:119`) → `hashlib.sha256` and is never read
  by anything else. Caveat: stdlib `http.server` pulls `zlib` into
  `sys.modules`; no zoo code calls it.
- **(c) the same shape for any POST — confirmed with caveat.** 6/6 `/v1/traces`
  variants (protobuf, JSON, gzip, empty body, bogus `Content-Type`, no
  `Content-Type`) → `200`, empty body, the request's own content type echoed and
  nothing invented when there is none. `/v1/metrics` → `404` **and the bytes are
  really recorded**: `rejected/0001.body` is `cmp`-identical and sits on an
  independent counter (`0001` while raw was at `0006`). Caveat: `GET` → `501`
  with the stdlib's 481-byte HTML page (specified §3.4, untested), and every
  answer carries a `Date` from the real clock — shape-invariant, not
  byte-invariant.

### 1.2 Claim 2 — A2, the Collector (`8c8299f`)

Run against the real binary. `make collector` fetched 0.162.0 and the digest
check genuinely ran: `sha256 fcc063749f730f8c21fe29f2d340ff174f5f1c5885bd3156fb6c985a3036fcc3 matches collector/SHA256SUMS`;
flipping one hex digit produced `REFUSING to unpack` and extracted nothing.

Ids were extracted **by the reviewer**, not read off the test's assertion — a
hand-written varint decoder on the raw side, stdlib `json` on the other:

```
raw/0001.body   128 bytes, not UTF-8 decodable (protobuf)
json/0001.json  valid OTLP JSON
trace  4bf92f3577b34da6a3ce929d0e0e4736   (both sides)
span   00f067aa0ba902b7                   (both sides)
name   GET /checkout                      (both sides)
```

Write-before-forward holds in the code — `sink.py:158` write under lock → `:174`
manifest → lock released → `:179` tee → `:205` forward — **and is guarded**:
forwarding first fails `test_the_body_is_on_disk_before_the_forward_is_attempted`
(`assert [None] == [b'\n~\n!...']`). Note the real-Collector test does *not*
catch that mutation; the invariant rests entirely on `test_tee.py`'s `Spy`.

### 1.4 Claim 4 — the operator flow, as shipped

**Headline: yes.** A stranger following `README.md` gets a correct, verifiable
capture on the first try. One stock-SDK OTLP/HTTP protobuf export (`opentelemetry-sdk`
+ `opentelemetry-exporter-otlp-proto-http`, one span) landed as 283 bytes of real
protobuf; the Collector re-encoded it to 657 bytes of valid OTLP JSON; ids match
(`trace af5c77d1f83cd5b9cf5b625a813bbd03`, `span 55568e44c773902c`). `kill -INT`
exited 0, both sinks and the Collector went down, no orphan held a port, the
manifest finished. **`make verify` → exit 0**; `make check` → exit 0 with the real
capture in the tree. `make collector`: digest verified, 5.9 s.

Where the README is **right**, verified: the `404`/`rejected/` path (R12); the
run-dir-reuse refusal, whose message is excellent (R11); non-zero exit with the
manifest naming failed forwards — provoked by `kill -9`ing the Collector:
`CAPTURE_EXIT=1`, `forwards: [{"error": "ConnectionRefused…", "file": "raw/0001.body"}]`,
body and digest intact (R8); the tee topology and both-directions verify (R14);
and the manifest-copy wording, which is precisely worded (R13).

**(B) The project manifest is copied at the START.** Settled empirically, not from
the code. While the capture was running and before any export, `MANIFEST.json`
already held the full `project_manifest` with `bodies: []` and no `ended_at`. The
mutation test is decisive: the source manifest was changed mid-run to
`model: stub-model-2-MUTATED` plus a new key, and what landed after `Ctrl-C` was
byte-identical to v1 (`landed == v1: True`, `has MUTATED key: False`). Captures
started *after* the mutation carry v2 — the copy tracks process start only. So
the "is" half of the open decision is answered; the "ought" half remains the
maintainer's.

**(C) One readiness line exists, but a script can only use it via a log file.**
`zoo capture: the raw bytes are the record. Ctrl-C to stop.` appears exactly
once, only after all three ports accept (measured: ports at T0+0.268/0.386/0.473 s,
line at T0+0.445 s with `connect 4318/4319/4320: OK` at that instant), and never
in `zoo sink`'s banner. But `recording POST /v1/traces on http://127.0.0.1:4318`
**is** a substring of both banners, so an unanchored grep is genuinely ambiguous —
and the obvious `| grep -m1 …` SIGPIPEs the capture into an unhandled
`BrokenPipeError` traceback, leaving a manifest with **no `ended_at`** (**F10**).
The verified wait-on-it form:

```bash
uv run zoo capture … > capture.log 2>&1 &
timeout 30 bash -c 'until grep -q "^zoo capture: the raw bytes are the record" capture.log; do sleep 0.1; done'
```

**F1 — `zoo verify <path>` can exit 0 on a capture it never checked.** A typo'd
run id, or a half-capture with `json/` but no `MANIFEST.json`/`raw/`, prints

capture can claim a Collector it does not have.** With a 6-line dummy holding
`127.0.0.1:4320`, the real Collector printed `failed to start "otlp" receiver:

recorded for 25 s with an empty `json/`. This is precisely the failure SPEC §4.6
says the refusal exists to prevent ("a capture *silently* missing its `json/`"),
and the only way found in this review for the operator to be lied to. Mitigating:
the per-body `!` line and the `1 forward(s) FAILED` summary do tell the truth at
the end. *(section-operator, R9)*

**F3 — the first `zoo capture` an operator meets does not run.** `README.md:57`,

**F4 — the open manifest-timing decision blocks run 2 as §2 scopes it.** §2
