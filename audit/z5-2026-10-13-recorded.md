## Method

1. `zoo replay --raw` into `spanweave-live serve`: every status, every event, the exit status.
2. `zoo replay --json` into `serve`. Completion is `serve --requests N`: after the Nth request the input has ended, and the end of input runs spanweave-live's `Run.finish()`, which replaces the completion with `Cap(0)` and ticks once, so every trace still held completes and is written (its SPEC §8.5 at the pinned sha). That is the `Cap(0)`-at-end the plan names, chosen by the receiver's CLI and not by the audit.
3. Each `json/` body re-read in-process by the pinned `spanweave_live.Endpoint`, each record partitioned by the pinned `trace_id_of`; per partition, the live file against `spanweave.build` of its records as JSON lines (`meta.source_digest` removed, spanweave SPEC §10.4) and against a `spanweave.Builder` fed them in order.
4. `spanweave inspect` on each written graph, verbatim; diagnostics by code, `unmapped_attributes` keys by size, `unknown` nodes.
5. `agentgolden.signature.signature(graph)`, no rules.

Steps 4 and 5 read the `Builder`'s graph (spanweave has no public reader from a graph document back to a `Graph`); step 3 compares its bytes with the live file's. The `listening` port and the clock readings in a `completed` event (`seconds`, and the two in its `detail`) are the receiver's and differ run to run; nothing else in this report does.
